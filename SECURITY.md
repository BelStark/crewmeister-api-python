# Security Policy

Report problems in credential handling, redaction, write confirmation, file
handling, dependencies, or distribution of the SDK, CLI, MCP server, and plugin.
Maintenance is voluntary; no support period or response time is promised.

## Reporting

Do not publish credentials, employee data, exploit details, or API captures in
issues or pull requests. On a published repository, use GitHub's private
vulnerability reporting feature under Security when available.

If no private reporting channel is available, ask the maintainer, BelStark, to
provide one without including sensitive details. Before public launch, the
maintainer must enable private vulnerability reporting or publish a monitored
private contact. This local repository does not claim that a remote channel
has already been configured.

Include the affected version, impact, and a reproduction using synthetic data.
Do not test against another person's account or real employee data. If a secret
has been exposed, revoke or rotate it promptly and coordinate cleanup privately.
